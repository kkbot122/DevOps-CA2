## Capture session (about one hour)

Run in this order, prioritizing the MUST evidence. Keep captures full-window and make the command line visible where applicable. The scenario run itself can overrun an hour; do not fake or abbreviate results to meet the estimate.

1. **Baseline and app state (5 min):** start the Grafana and Prometheus port-forwards with `make grafana` and `make prometheus`; open the dashboard at a 15-minute range. Run `make scenario-baseline`, then capture 01, 02 and 19 while real traffic is visible.
2. **Release behavior (10 min):** capture the ready pods for 16. Run `make probe` in one terminal and `make good-release` in another; capture the overlap and final probe summary for 17. Run `make bad-release-crash`, then `make rollback` and `make history`; capture CrashLoop evidence for 07 and rollback history for 18. Use the committed result logs as report evidence if the live timing is inconvenient.
3. **Alerts (10 min):** run `make scenario-latency`; capture 03 and 20 while the alert fires. If time allows, run `make scenario-errors` and capture 04/06. Run `make scenario-redis-down` and capture 08; run `make scenario-surge` and capture 09. Do not run overlapping fault scenarios.
4. **Ansible (15 min):** use the disposable Ubuntu 24.04 target, not the unsupported macOS host. Run `make ansible-check`, `make ansible-apply`, `make ansible-idempotence`, `make ansible-verify`, capturing 21–24. Run drift demo only if the disposable target is ready; capture 25–26.
5. **Pipeline evidence (10 min):** open the private GitHub Actions run and settings pages. Capture 10–15 and diagram 27. Mask tokens, personal profile details, and unrelated repository information.
6. **Review (10 min):** confirm each image is at least 1280 px wide, readable, correctly named, and has no exposed credentials; run `make screenshots-check`.
